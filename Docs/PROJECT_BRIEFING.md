## 0. 一分鐘版本

**Nice Ink** 是一款 4–6 人第一人稱派對遊戲。UE 5.7，純 C++，**零 Blueprint、零 UMG 資產**。

> 一群日本大相撲力士帶著現金在道場喝酒。被酒瓶選中的人喝下一杯就閉眼醉倒；
> 其他人拿刺青機在他赤裸的身體上亂畫（會消失的刺青）。他什麼都看不見，
> 只能在醉夢裡沿著一個圖案的輪廓「割糖餅」式描線來掙扎甦醒——而畫的人可以花錢
> 搖晃他的夢來拖時間。他描完就**無聲睜眼**（沒有任何系統提示），可以裝睡靜觀、抓人現行。
> 他起身後，全員同步輪看每一幅作品，他挑一幅、指認作者：
> **猜對**＝作者換上來被畫；**猜錯**＝那幅當場變成碳黑刺青（洗不掉，只能花錢雷射三次），
> 再罰一杯酒、繼續被畫。**連續三杯**＝昏死不醒＝終局：現金被瓜分、全員在他身上塗鴉、
> 舊碳黑被二氧化鈦鎖成永久刺青。

設計主目標（SPEC 明文）：**讓精彩、有意義的內容趨近於無限**——遊戲只提供平台與工具，
內容由玩家之間的碰撞產生；行銷主力是短影音，所以「靜音可讀、零上下文可讀」是第一優先。
次要目標：**陌生人局也要成立**——判讀證據不可依賴社交知識（聲線、畫風先驗、交情 meta）。

## 1. 題材與世界觀

- 場地＝相撲部屋的**道場**（`L_Dojo`：木地板／障子／榻榻米；實測 14.2×7.6m 長廳，
  拉門在東西兩端，21 個獨立部件 actor）。舊的桑拿房 `L_Sauna` 保留可切回。〔碼〕
- 角色＝統一的胖力士體型（掃描重拓樸的 `SM_Sumo`／`SK_Sumo`，37 骨含 5 顆 Jiggle 骨），
  全員**標準髮髻（丁髷）＋一條褌**，其餘照裸。玩家的**自拍臉**貼到這具統一身體上。〔碼〕
- 題材動機（承重、不可動）：**現實中日本相撲協會真的禁止力士刺青**。所以他們玩這個
  遊戲互相刺青——會消失的那種。這條現實規則讓墨水三階段各自有現實重量：
  會消失的刺青＝安全的過癮；碳黑＝生涯危機；永久＝職業死刑（被逐出相撲界）。
- 服裝規格同時是**平台合規決策**：褌遮住屁溝／陰部／肛門（任何平台都絕對過不了的區域），
  屁股蛋、大腿內側、乳頭照裸照畫。「相撲」是全世界唯一「近裸胖男＝運動而非裸體」的
  既成圖像類別——這是短影音**推薦資格**的護城河（禁播不是威脅，不被推薦才是）。
- 全程**無超自然元素**（醉夢是醉倒者腦內的夢，不算）。

## 2. 一場遊戲的完整流程（以實作為準）

伺服器權威的相位機在 `ANiceInkGameMode`／`ANiceInkGameState`（列舉 `ENiceInkPhase`）：〔碼〕

```
Lobby ──(房主按 ENTER；正式版 4 人門檻、PIE 2 人)──► BottleSpin
  └► Seating ► Drawing ► Tour ► Accusation ► Resolution ─┬─► Seating（下一回合）
                                                          └─► Finale ► PostGame
```

| 相位 | 實作時長 | 內容 |
|---|---|---|
| `Lobby` | 無限 | 大廳：席位／臉像／名字／現金列表、房間碼大字、房主按 ENTER 開局、房主可 ESC 踢人 |
| `BottleSpin` | Gather 2.5s ＋ Spin 4.0s | **只在開場**：全員走到圈上站成一圈 → 酒瓶在圈心轉、慢慢停在被選中者正前方 |
| `Seating` | Approach 1.6 ＋ PickUp 1.2 ＋ Drink 1.8 ＋ Collapse 1.1s（儀式關閉時 fallback 3.0s） | 受害者走進圈心、俯身拾起酒瓶、仰頭喝、醉倒在原地。**每一回合都走這段**（入座酒與罰酒共用同一序列） |
| `Drawing` | **沒有計時器** | 作畫階段。長度＝受害者的醉夢描圖進度；受害者按 WASD 現身即當場收束 |
| `Tour` | 20s × 作品數 | 傑作巡禮：系統鏡頭逐幅聚焦，全員同一時段看同一幅 |
| `Accusation` | 無限（等受害者送出） | 指認：受害者選一幅作品 ＋ 選一名嫌疑人 |
| `Resolution` | 6s | 結算演出：鏡頭聚焦被選那幅；+1.2s 時（猜錯的話）當眾轉碳黑；全場洗掉其餘會消失的刺青 |
| `Finale` | 30s | 終局羞辱時間：全員可在輸家身上塗鴉 |
| `PostGame` | 無限 | 場間大廳：第三人稱端詳自己的刺青；按 `L` 花錢雷射；房主按 ENTER 再開一場 |

**關鍵不變量**
- 作畫階段**沒有固定秒數**——「不知道他何時醒」是這個階段唯一的張力來源。〔碼〕
- 受害者按 WASD＝現身，作畫**當場收束**；不設收尾倒數、不設保底計時。〔碼〕
- 巡禮清單只收「受害者畫布上、狀態＝Marker、有筆劃、AuthorId ≥ 0」的作品；
  **稿線（Stencil 針）在進巡禮之前全部洗掉**（稿是導引不是作品）；
  **完全沒人動筆＝跳過巡禮與指認，同一位受害者再睡一輪**。〔碼〕
- 罰酒計數只數罰酒（`PenaltyCups`），猜對離座即歸零，第三杯＝終局。**與人數無關**。〔碼〕

### 2.1 入睡儀式（零硬切）

分拍狀態機 `ENiCeremonyStep`：`Gather → Spin → Approach → PickUp → Drink → Collapse`。〔碼〕

兩條使用者定案撐起整段實作：
1. **先抽後演**——伺服器先均勻抽定人選，酒瓶只是把結果演出來。
   （席位角度不等距，真物理＋扇區判定反而會偏心；均勻抽才是真公平。
   這不違反「純儀式、零規則」——儀式本來就是決策的展示。）
2. **都不要有硬切**——全程**零 `SetActorTransform`**：走位走合成輸入
   （`AddMovementInput`，與真鍵同一入口），**崩塌終點 ≡ `GetVictimLieTransform()`**，
   於是睡姿接管當幀零跳變。

客戶端所有儀式視覺都是 `(Step, t, GameState 複製參數, 世界幾何)` 的**純函式**——
無狀態、無累積、遲到者自動對齊。`bCeremonyEnabled=false` 可一鍵退回舊制傳送。〔碼〕

**這是美術語言的明文例外**：「程式化硬轉、突兀即目標」管的是**玩家動作**的即時回饋
（彎腰／起身）；**系統演出走連續**。

### 2.2 舞台位置

單一來源＝`EnsureStageGeometry()` 把幾何寫進 GameState。〔碼〕
- 受害者躺位 `VictimLieSpot = (430, 40)`＝榻榻米中心＝儀式圈心＝崩塌終點
  （一個位置、三個身分）。
- 六個席位＝繞它半徑 230cm 的六等分環；儀式圍圈半徑 160cm。

## 3. 作畫系統（遊戲的主體驗）

### 3.1 貼臉鎖定（lean-lock）

- **沒有預切平面——你的視野就是畫布。** 站著用準星看向想畫的部位，按右鍵＝湊上去：
  射線必須命中另一名角色、且該點能解出身體 UV 才成立。〔碼〕
- 入鎖後：相機硬切到皮膚上方的特寫、**FOV 36**（使用者二調定值——
  「投入是要付代價才能脫離的狀態」），自己的身體不渲染（OwnerNoSee），
  畫面上只剩皮膚。〔碼〕
- 鎖定＝**自願失明**：畫畫時看不到房間（畫臉除外）。
  「多畫一筆 vs 抬頭看他的眼睛」由此機械化——每個作畫者都在自己選擇的失明裡。
- **共同作畫允許**：多人可鎖定重疊區域、即時同步彼此筆跡；筆劃帶作者 ID，
  碳黑轉換只作用該作者的筆劃，重疊作畫不會互相污染。
- **近臉作畫原則**：報酬越高的部位（臉、屁股蛋、大腿內側）風險越高，
  是由幾何自然形成的——畫臉＝畫面內自帶他的眼睛（免抬頭，但你也在被抓現行的最近距離）。

### 3.2 三工具制（`Q` 循環；09-02 前為滾輪）〔碼〕

| 工具 | 手感歸屬 | 規則身分 |
|---|---|---|
| **打稿筆 Stencil**（預設） | 手擁有速度與路徑：滑鼠純積分推游標、自由直畫 | 結晶紫 `#703593` 固定色、不吃調色盤；**不進巡禮、不可指認、甦醒收束時全洗** |
| **割線針 Liner** | **機器擁有速度**：針以 `v_max` 上限追趕自由游標；落針壓在稿線 1.5cm 內＝**沿稿自動走**（動滑鼠即取消） | 會消失的刺青 |
| **填色針 Shader** | 手擁有速度，機器擁有「單趟的薄」：沿路徑每 0.2cm 一枚低濃度軟章，疊趟收斂實墨 | 會消失的刺青 |

這一組對應現實刺青工作流：**紫麥克筆打稿 → 機器沿稿上墨 → 填色**。

速率守恆式（嫌慢只准動 `TattooDotHz`）：〔碼〕
```
v_max = TattooSpacingK(0.5) × TattooNibDiameterCm(0.30) × TattooDotHz(12) = 1.8 cm/s
```
筆寬 3.0mm 全身一致（`MarkerUvRadius 0.000452`；墨水圖集 UV0 是**均勻紋素密度**，
實測 0.617 px/mm）。**細筆尖是不變量**：皮膚是跨場的不可再生資源，細筆控制通膨，
讓第十二場的身體仍是可閱讀的恩怨史。

其他實作事實：
- 出墨的物理因果＝**LMB 按住＝針伸出**（伸長量一半給針、一半給握管）。
- 第一人稱看到的是 **2D viewmodel 貼圖筆**（永遠同大小同位置、零穿插）；
  旁人看到的是 3D 刺青機／麥克筆模型（世界真相層）。
- 作畫時除自己與沉睡者外，其他人變半透明 ghost 且可穿過（`M_GhostBody`）。

### 3.3 相機與游標（踩過最多坑的一段）

- **稿筆**：相機**恆凍結**（真靜止的紙＝自由手繪的參考系）。唯一例外是**邊緣推擠**——
  把游標標記推到視窗邊緣、還持續往外推，視野才讓位，**推多少給多少**；
  **左鍵按住時視野無條件鎖死**。臉＝惰性追隨游標（時間常數 0.22s，
  第三人稱「臉追著筆走」的讀感）。〔碼〕
- **機器工具**：畫面歸針（aim ≡ 針），行進蟻虛線＝針→游標的完整待走路徑、
  盡頭與游標十字重合。〔碼〕
- **鐵則**：游標類輸入**不做「狀態機＋否決」**——滑鼠純積分、落點永遠用「讀」的
  （射線命中什麼就是什麼）、打不到就收筆並畫個 ✕（純回饋），游標移動本身永不被干擾。
  這條是「輸入所有權歸玩家」的架構義務，違反它的三個版本都被使用者打回。
- **滑鼠靈敏度**＝設計基準 × 玩家偏好 × **FOV 縮放**（開鏡定律：鎖定 FOV 36 對站姿 90，
  不縮放就是游標三倍速）× `DrawSensitivity`。〔碼〕
- 濾波：One Euro 濾波器**預設關閉**（2026-08-25 延遲戰役）；
  引擎的 `bEnableMouseSmoothing` 也已在 `Config/DefaultInput.ini` 關掉——
  它會在手停下後繼續合成位移，推翻程式裡「靜止不抖是構造保證」那句話。〔碼〕

### 3.4 可畫域＝嚴格最大橢圓

入鎖時對鎖點鄰域做 64² 可行性採樣（眼錨可見性 trace ＋ 姿勢解算可行性），
擬合「內部無不可解樣本」的**最大面積橢圓**：無下限、無人工放大——
太小就是太小＝誠實訊息，玩家自己重鎖（實測腹頂 ≥1.6×A5）。〔帳＋碼〕

- **單一裁判**：墨閘／收筆／HUD 提示／筆尖紅 ✕ 全部查同一條橢圓公式。
- 顯示＝本人專屬的「靜音層」皮膚紗（`M_ReachVeil`，材質內解析橢圓公式；
  柔灰暖膚保留膚色 ＋ 固定公分寬對角柔帶）。零貼圖、零斑點。
- 「大筆一揮塗滿全身」在物理上不可能——覆蓋率被空間限速。

### 3.5 作畫姿勢（**與 SPEC 敘述不同，見第 12 章**）

實作＝**使用者手擺的兩個端點姿勢之間插值**（`Source/NiceInk/Private/DrawPoseData.h`，
由 `sumo_retopo_base20.blend` 匯出：`DrawPose_Backup2`＝盤腿坐直基底、
`DrawPose_Backup4`＝站立前傾半蹲（髖 68cm、腳跟離地腳尖踩地、右手前伸））。
程式只在基準附近施加小幅增量（Hips 傾多傾少、Neck 對準臉向、整身 yaw）。
原始碼註解明寫：**「程式不發明姿勢」**。〔碼〕
右臂另有兩骨解析 IK 跟著實體筆走。

### 3.6 墨的資料模型

`FInkStroke`（UV 折線或點刺、顏色、針型、逐點流量）→ `FInkWork`（一位作者在一個回合
畫下的全部筆劃＝**傑作**＝巡禮／指認／碳黑／鈦白／雷射的原子單位）。〔碼〕

- 渲染＝`UInkCanvasComponent` 的三層 Render Target（線層 4096＋Valve alpha 銳化／
  霧層 4096 軟半透明／刺青層）。**2026-08-25 起惰性配置**：只有真的有東西要畫的層才
  配置，缺席的層綁 4×4 全透明替身（傳 nullptr 會退回材質預設灰格＝整身變灰）。
  受害者入睡時預熱線層／霧層，避免第一針掉幀。〔碼〕
- 網路模型：作畫者送 Server RPC → 伺服器驗證（相位／身分／目標）→ 由**被畫的角色**
  multicast 重播到所有端 → 每端各自在本地重建 RT。客戶端有**本地預測**
  （當幀上屏，用序號回播對消）。〔碼〕
- 世界↔UV 雙向解算在 `UInkBodyComponent`（tri-cache、焊接拓樸、表面攤平補丁
  `FInkSurfacePatch`、縫資料層——跨縫的面積章走「表面攤平補丁逐點落墨」）。
  2026-08-25 兩個方向都接上空間索引：世界→UV **7.10ms → 0.012ms**
  （598 倍、2200 樣本輸出逐位相同）。〔帳〕
- **改 UV0 排布＝舊存檔的刺青座標全部作廢**（鐵則）。

## 4. 沉睡者：醉夢描圖（甦醒小遊戲）

### 4.1 感官規格（判讀系統的地基，每一條都是刻意的）

- **視覺全遮蔽**：黑屏。看不到任何人（連剪影都沒有）、看不到落在自己身上的筆跡、
  也看不到自己身上既有的刺青。畫面上只有兩個元素：**描圖盤**與**姿勢面板**
  （自己身體的示意圖，顯示當前姿勢與朝向——被翻面會反映）。
- **姿勢面板永不顯示墨跡的即時變化**（護欄：看得到即時筆跡＝可以掐時機精準反擊，
  整個瞄準博弈會塌）。
- **聽覺開放**：全房語音照常聽得到，**無方位**。方向只能靠語音**內容**推理，
  而內容可以說謊——謊報位置是正當戰術。
- **全域靜音**：閉眼沉睡時遊戲音效全部靜音（筆劃聲＝情報）。
  **語音與 BGM 不經此層**——語音走 EOS SDK 的音訊裝置（構造保證），
  BGM 恆定播放且不對任何遊戲狀態反應（零洩漏的構造保證）。〔碼〕

### 4.2 描圖玩法

`UDreamTraceComponent`：受害者 client 本地模擬＋繪製，**狀態不複製給任何他端**——
作畫者全程看不到夢的進度。〔碼〕

- 畫面上一張**一筆畫圖案**，沿著它的路線帶描線；**下針中針心離開帶＝失敗**：
  已描的線全洗、針回起點、**同一張圖**重描（圖不換＝路線記憶是玩家自己的資產，
  失敗可歸咎於手）。
- **描完整條路線＝無聲甦醒**（睜眼、零提示）。
- **延遲甦醒是合法策略**：最後一段留著不描，聽到房間畫得最熱烈時才收尾，
  換一網打盡的目擊。
- 操作與割線針**完全同制**（使用者鐵則：不准機制分岔）：自由游標（純積分、無皮繩、
  無域牆、可放很遠）＋針以 v_max 追趕＋FP 刺青機貼圖＋行進蟻虛線＋游標十字。
- 呈現＝圖案包圍盒貼滿可用螢幕域（佔螢幕高 72~78%）；姿勢面板撞到才讓位。
  放大率與游標增益都與割線視圖同源（同一公分在螢幕上一樣大）。

### 4.3 圖案池與難度（實作值）〔碼〕

八式，全部來自現成向量圖源（Twemoji CC BY 4.0 ＋ Wikimedia 折鶴 CC BY-SA 3.0），
**純外部輪廓**（內輪廓在剪影語言裡是噪聲），種子選圖＋鏡像：

| 罰酒杯數 | 圖案池 | D_shape 難度 |
|---|---|---|
| 第一杯 | 扇／糰子／雙浪／龜 | 1.03~1.65 |
| 第二杯 | 折鶴／鳥居 | 2.86~3.47 |
| 第三杯（生死局） | 櫻／蛇 | 4.29~4.44 |

- **時間統一 60 秒、不隨杯數**（時間服務的是作畫者的內容預算＝每回合恆定需求）；
  線長是導出量＝時間 × 針速（`60 × 1.8 = 108cm`）。
- **帶全寬＝筆寬 × 2.4**（統一，使用者定值）——難度純走圖案複雜度軸。
- 深杯實際變長的來源是失誤率＝可歸咎於手。
- 圖案來源鐵則：**不得由程式手雕座標**（美學裁決不歸程式）。

### 4.4 搖晃攻擊（金錢第一次流進回合中）〔碼〕

作畫階段，任何非受害者按 **G**：花 500 元讓受害者夢中的圖搖晃 2.0 秒、振幅 1.2cm，
每人冷卻 4.0 秒。

- 座標系設計是這個機制的核心：**針活在盤面空間、圖活在圖形空間**——
  搖的是圖不是針（針＝你的手），所以「圖搖走、手沒跟上」＝針在圖上滑出帶＝重來。
- **抬針＝安全**：攻擊買到的是「強迫暫停」，硬描過去才會翻車（受害者有反制）。
- 受害者看得到攻擊者的名字（怒氣要有地址）；其餘玩家不通知。
- 睜眼後照收照扣（無聲甦醒零洩漏）。
- 時鐘所有權因此翻轉：舊制「作畫者無法主動拖延時鐘一秒」已明文廢止。

### 4.5 翻身表決（F 鍵）〔碼〕

作畫階段，任一作畫者按 F＝提案翻面；**其餘全體非受害者全數同意**才執行
（非 ragdoll，正面／背面各為固定姿勢；醒來自動回正面）。
這是把受害者背面（屁股）變成畫布的唯一手段，也是姿勢面板在 v1 的主要用途。

## 5. 無聲甦醒與裝睡

- 描完＝睜眼。**沒有任何系統提示**：不通知作畫者、不播音效、不打斷任何人。〔碼〕
- 睜眼後滑鼠直接操縱**臉指向**（方位＋俯仰）：頭沿**轆轤首伸縮脖**升起約 46cm 環視全房。
  頭部姿勢與抬升是指向的**純函數**——玩家不持有任何姿勢自由度；
  俯仰域＝逐方位量測烘入的鉗位表。
- 相機嚴格＝眉心＋臉朝向，FOV 72：
  **你看得到的 ≡ 你的臉表達的 ≡ 旁人讀到的破綻**。
  窄 FOV＝找人要多掃視＝破綻更多（對視保證）。
- **裝睡＝按住 Shift**：立刻回到沉睡姿勢＋閉眼貼圖，對旁人與真沉睡**視覺上不可區分**；
  放開＝回到按下前的臉指向（實作＝指向凍結，不做存／還原＝沒有可以錯的第二份狀態）。
  裝睡期間**本人畫面全黑**——臉表達沉睡＝自己也看不到，裝睡不是免費監視器。〔碼〕
- **按 WASD＝現身**：身體起身、作畫階段當場收束、直接進巡禮。
- 作畫者能觀察到的破綻只有兩個：**睜眼的貼圖變化**與**頭部的轉動**。
  所以「低頭偷看自己身上被畫了什麼」這個動作本身就在暴露甦醒。
- 睜眼但還沒現身時，本人看得見自己的身體與正在落下的筆跡（抓現行要有畫面）。〔碼〕

技術：頭與身體沿使用者手標的縫 `cut_seam_head3`（84 頂點）**真切開**，
中間的脖子由 `UNeckStretchComponent` **每幀重新解出銜接曲面**
（無材料身分、素膚材質、非畫布——它不是被拉扯的物體，
是「此刻怎樣的脖子銜接看起來正常」的解）。站立／作畫／睡覺全狀態共用同一條程序化脖子。〔碼〕

## 6. 巡禮 → 指認 → 結算 → 終局

### 6.1 傑作巡禮（每一局的情緒爆點）
系統鏡頭逐幅聚焦（`ViewWork`），每幅 20 秒，全員同一時段看同一幅。〔碼〕
**巡禮是真正的初見**：受害者全程看不到任何筆跡，第一次知道身上被畫了什麼就是這一刻，
驚訝是真的。（舊版讓靈魂看著每一筆落下，情緒在作畫階段就分期付款花完了。）

### 6.2 指認（每回合恰好一次）〔碼〕
受害者：數字鍵 `1`–`9` 選作品（鏡頭同步聚焦該幅預覽）、`Tab` 循環嫌疑人（依席位排序）、
`ENTER` 送出。
- **猜對** → 該幅作者成為下一位受害者；罰酒計數歸零。
- **猜錯** → 真作者揭曉（全員都知道那幅是誰畫的）、被選那幅轉碳黑、罰酒 +1、
  同一人再被畫一輪。
- 其餘會消失的刺青與證據標記在結算時全部洗掉。
- 碳黑一誕生就即刻落盤＋上雲（不等終局——中途斷線不丟碳黑）。

### 6.3 終局〔碼〕
輸家的現金被其餘玩家平分（輸家歸零）→ 羞辱時間 30 秒（全員可在他身上塗鴉）→
相位結束時把他身上**所有碳黑（含過去場次殘留的）自動鎖成永久** →
所有會消失的刺青（含羞辱塗鴉）洗掉 → 跨場資產落盤 → `PostGame`。

### 6.4 場間大廳（PostGame）〔碼〕
第三人稱跟隨鏡頭（轉身就能看自己身體各面，SPEC 視角規則：局內第一人稱、局末第三人稱）；
按 `L` 花 2000 元雷射自己最舊的一幅碳黑（每次淡化一級，**三次徹底清除**；
永久刺青無效）。房主按 ENTER 再開一場，刺青與錢包跟著走。

## 7. 資產階梯與經濟

| | 會消失的刺青 | 碳黑刺青 | 永久刺青 |
|---|---|---|---|
| 怎麼來 | 作畫階段自由畫 | 受害者猜錯時，**被選中的那一幅** | 終局，二氧化鈦刷過碳黑 |
| 怎麼消失 | 每回合結算全洗；遊戲結束全洗 | 場間大廳自費雷射，三次徹底清除 | 永不消失（已淡化的鎖在淡化態） |
| 跨場 | 永不 | 跟著角色走 | 跟著角色走 |

- 入場現金預設 `Cash = 10000`〔碼〕；遊戲進行中猜錯**不扣錢**（代價是皮膚）。
- 錢的出口有二：**雷射**（場間，洗自己的皮膚）與**搖晃攻擊**（回合中）。
  沒錢雷射＝把負債帶進下一場：再輸一次那些碳黑就會被鎖成永久。
- **賭注加權**（所以不需要「至少畫一筆」的強制規則）：受害者傾向選「就算猜錯、
  變成刺青也不痛」的溫和小品來猜 ⇒ 擺爛的無害塗鴉最容易被送上中央；
  畫得**超級過分**的傑作沒人敢選 ⇒ 其作者反而最安全。
  第二杯起進入生死局，受害者被迫改猜辨識度最高的大作 ⇒ 大膽作品的豁免權自動失效。
- 跨場持久化：`UNiceInkSaveGame`（現金＋碳黑／永久刺青）。
  存檔鍵＝**EOS ProductUserId**（LAN／PIE 無 PUID 時 fallback 舊制玩家名＋席位）。〔碼〕

### 判讀資訊排序（常駐設計參考，動任何相關系統前先看）
v1 陌生人場的實際排序：**抓現行 ＞ 語音內容推理 ＞ 場內累積畫風**。
（原本排第二的「噴漬／瘀青標記」隨噴射拳腳移出核心循環而暫缺——
「第二名管道缺席下核心循環是否成立」正是 v1 要驗證的主命題之一。）
朋友場則在同樣的硬管道上疊一層軟知識（幽默感、膽量、選色習慣、恩怨史）。

## 8. 身分系統（臉＋名字雙載體）

**強制上傳制**（使用者定案）：**不上傳照片就不能開始遊戲**——首次啟動落在
「創建你的力士」導流頁（無返回、無 ESC），臉一到手才進主選單。〔碼〕

- 所有身分顯示點（大廳名列／巡禮揭曉／指認嫌疑人／頂欄受害者）＝**臉像＋名字並列**。
  底層唯一鍵是隱形的 PUID；名字是顯示層、允許重複、永不作身分判定。
- 有效名 ＝ 自訂名 ＞ 平台帳號名（現行 Epic；上 Steam 後同一條 OSS 介面自動變 Steam
  persona）＞ session 保底 `rikishiNNN`（不落檔）。名字開放 Unicode
  （黑名單式消毒、上限 16 碼元；顯示端另有寬度截斷）。〔碼〕
- **自拍→臉貼圖管線已完全內建進遊戲**（C++/ONNX，`Source/NiceInk/Private/Face/`）：
  MediaPipe 特徵點（兩顆 tflite 經 tf2onnx 同權重直轉）＋ BiSeNet 分割 ＋ LaMa 修補
  ＋ TPS 變形，全部走 NNE（NNERuntimeORT）與引擎自帶 OpenCV。
  產出四工件：`face_open`／`face_closed`／`eye_mask_ink`（眼球禁畫遮罩）／`skin_color`。
  實測耗時：暖 88s、冷 156s；打包版 Development 實測 34s。〔帳〕
- **臉庫**：每次上傳都保存（`Saved/PlayerFace/library/<時間戳>/`），`active.txt` 指針，
  選單縮圖列點選即換。縮圖＝`ANiceInkPortraitBooth` 頭像亭的 3D 肖像
  （隱形攝影棚：正交投影＋透明底＋六面均勻點光＋膚色錨定自動曝光＋
  深度遮罩上下分域「殺肩保髷」）。〔碼〕
- **房內分發**：`UNiceInkFaceShare` 登記簿（席位→三貼圖＋膚色＋版本）＋
  分塊 RPC 列車（16KB＋CRC；NIF2 壓縮＝JPEG q90＋alpha PNG 分載，1.5MB→~400KB），
  主機集散、晚到者補發。房內每個人看到的是彼此的真臉。〔碼〕
- **隱私聲明**（常駐在上傳處，每一句都必須在現在與未來的架構下恆真）：
  照片只在你的電腦上處理、我們沒有伺服器、開發者永遠不會收到你的照片、
  只有同房間的玩家看得到你的臉。
- **選單背景跳舞的預設力士＝作者本人的臉**（`Content/AuthorFace/`）；
  玩家上傳後只能用自己的照片——**作者臉永不成為玩家可選項**（構造保證，
  只活在選單舞台的預設分支）。
- 眼球是**唯一的規則級繪畫限制**（禁畫）；褌下的皮膚畫不到是**物理遮擋**，不是規則。

## 11. 美術與呈現

- **光照＝fullbright 均勻亮**（放棄寫實光照）：作畫要蜷縮貼近身體，自遮蔽是物理必然，
  寫實光照無論怎麼打都與「畫作要被看清楚」作對——而判讀排序是全設計的承重不變量，
  光照必須讓位。
- **皮膚質感配方**（全部住在角色材質裡、不加任何光源）：全啞光（Specular 歸零）
  ＋**頭燈假光**（面向鏡頭的程度決定亮度＝把判讀寫進光照定義）
  ＋**血色色度場**（從掃描 albedo 抽純色度、丟棄全部亮度）。
  **皮膚零烘焙陰影是鐵律**——任何暗紋都會被讀成身體特徵、與筆跡搶注意力。
- **褌＝弓形實體**（`Tools/AssetPrep/fundoshi_arc.py`）：裁切域是整形後的皮膚本身、
  剖面是測地距與局部帶寬的圓弧、接觸線沉 0.8mm、單網格水密、無上緣無牆。
  **玩家看到的黑／膚交界不是接觸線**，而是 `h=0` 等值線（內縮 1.2~2.4mm，
  由局部帶寬決定）——這個認知花了六天、十五個 commit 才換到。〔帳〕
- **走路＝程序化摺り足**（力士滑步）：雙腳恆貼地（構造保證）、撐地腳世界釘住、
  步幅＝速度/步頻守恆式、雙軌側帶鉗位（構造保證不越中線、不穿膜），零動畫資產。〔碼〕
- **軟肉彈跳**：五顆 Jiggle 骨（肚／胸×2／臀×2）世界空間阻尼彈簧＋旋轉耦合
  （明暗隨肉滾）。不變量：**停下就回原位**（雙門檻後寫入精確 rest，
  不靠指數衰減漸近）。〔碼〕
- 美術語言（常駐原則）：**用簡單、明確、浮誇的大動作直接呈現玩家在做什麼；
  程式化硬轉，不做平滑補間的「自然感」——突兀就是要的效果。**
  唯一明文例外＝系統演出（入睡儀式）走連續。

## 15. 給接手模型的工作守則（專案鐵律摘要）

1. **使用者的 viewport 是唯一驗收閘門。** 你的截圖只能證明幾何成立，
   永遠不能宣稱「效果很好」。robo 測試通過 ≠ 完成。
2. **設計捕捉一字不改。** 使用者第一次講機制時逐字記錄；不要問他的話裡已經回答的問題。
3. **「給我洞見／分析」＝只分析，不寫 SPEC。** 只有使用者明說「更新進專案」才動 SPEC。
4. **不要 hedge-and-propose。** 給一個明確推薦＋理由，不要列選項清單讓他選。
5. **不要重提 SPEC 已有的東西當新點子。** 提案前先搜尋 SPEC。
6. **誠實報告。** 測試失敗就說失敗並附輸出；跳過的步驟明說；不確定的標注不確定。
7. **量測，不要猜。** 卡住時第一步是把現場數字抓出來（座標、距離、狀態布林），
   不是盯著程式碼想。
8. **契約不可只驗上限。** 「不該跳」若只寫「位移 < X」，那麼「什麼都沒發生」永遠通過。
   該動的必須同時驗「真的有動」的下限。
9. **註解裡的規模常數會過期。** 曾經有兩句過期註解複利成 43 倍的謊；
   凡是把規模／耗時寫進註解，就要有活體儀器盯著。
10. **動任何與判讀有關的系統前**，先回到 SPEC 的「判讀資訊排序」表，
    確認它動了哪一條管道。

專案的深度背景在記憶資料夾與 `CLAUDE.md` 的「UE 陷阱年鑑」——
那裡每一條都是吃過虧的「症狀→原因→解法」，動手前值得掃一遍。
