# 作畫相位 畫面清單（Draw HUD Inventory）

> **加一個元素之前，先讀完這張表。** 這份文件存在的唯一理由是 2026-09-02 的事故：
> `LINER` 同時出現在三個地方（針尖標籤／底部 cluster／提示行的 `Q needle`），
> 顏色出現在兩個地方。真因不是美感，是**沒有人擁有這個畫面**——我加 cluster 時
> 以為在收斂，實際上只拆了色票列，變成加第三份。
>
> 規則：**一件事只講一次，而且講在會被讀到的地方。** 新增一列時必須填滿
> 「何時消失」與「誰在讀」——填不出來的元素就不該存在。
>
> **這張表不寫數值，只寫旋鈕名**（秒數、尺寸、alpha 都在程式裡）——
> 註解裡的常數會過期，而且沒有東西在看著它（專案鐵律，血價見 SHIP_PLAN 追記80）。

## 承重前提：眼睛在哪

作畫時 FOV 36、相機凍結、畫面歸針 ⇒ **視線幾乎 100% 釘在螢幕中心（針尖）**。
這決定了每個元素的判決：

- **0°（螢幕中心）**＝落筆當下會被讀到 ⇒ 只有「墨會落在哪、什麼顏色」配得上這裡。
- **週邊（上緣／下緣）**＝只有停筆時才會被讀 ⇒ 放環境資訊與事件，不放操作狀態。
- **不會被讀的東西不該常駐**——它不是資訊，是雜訊。

| 十色票列（10 個色塊＋數字標） | 選項的可視化歸墨杯盤；常駐只需要「我手上是哪一杯」 |
| 數字鍵 1–0 顏色快捷（`PollPalette`） | **顏色↔數字是任意映射**（紅色是 1 還是 7 沒有道理，只能背）＝熟練度分級通道，而這是派對遊戲。它同時是三個 bug 的來源：站著也生效但無回饋／拿稿筆時改了色而落墨仍是紫（延遲生效的假選擇）／十色順序是唯一需要被記住的理由。**對照組：滾輪→濃度留著**，因為那是自然映射（有序手勢配有序軸，不用背） |
| 托盤左側的三個列標（100%/60%/30%）＋第二、三列杯子 | **09-03 二修**：打霧筆的盤從 10×3 收成一排。二維方向選擇會讓「往右換個顏色」順手改掉濃度，而**濃度誤用單向不可逆**（要 30% 卻下了 100% 救不回來，反過來再掃一趟就補滿）；盤有三種形狀＝三套肌肉記憶；濃度已經有滾輪（自然映射、不開盤也能調）⇒ 盤再做一次＝兩條通道做同一件事。**教學沒變弱反而更強**：滾輪一滾整排一起變淡＝因果直連的動態示範，而三列並排是靜態的（玩家得先假設那三列是同一個東西的三種樣子才讀得懂） |
| 托盤下緣的欄標鍵帽（1..9,0） | 它唯一的用途是教「哪個數字＝哪個顏色」；快捷退役後它就從教學變成指向不存在的東西。**刪了快捷卻留著標示，比兩者都留更糟** |
| 螢幕中心下方的 `RMB — lean in` 整句 | 同一畫面右緣已經是鍵帽列 ⇒ 一種東西兩種形式兩個位置。句子裡的 "RMB" 不會被讀成一顆可以按的鍵（09-02 已為 Q 學過同一課）——留下的是鍵帽那份 |

## 鐵則：**「在任意背景上可見」有四類手段，顏色只是其中一類**（2026-09-03，六版收斂）

指示器原本畫成「當前墨色」——看起來理所當然（它就是要告訴你墨是什麼顏色）。但
**最常做的事就是在剛畫好的墨上繼續畫**，那時指示器與底同色 ⇒ 對比為零、整個消失。
**最常見的使用情境剛好是這個畫法的最壞情況**，而它在乾淨皮膚上永遠看不到。

我在「顏色對比」這一個維度裡打轉了四版（固定黑白 → 讀中心一點 → 逐段取樣 →
WCAG 連續求解），直到 user 追問「業界用什麼手段」才發現**手段有四類**：

| 類別 | 做法 | 需要知道底色嗎 |
|---|---|---|
| 顏色對比 | 反相／黑白雙線／動態求解 | **要** |
| **自己製造背景** | **陰影／暈／半透明底板** | **不用** |
| 運動 | marching ants（人眼對運動的敏感度遠高於對比） | 不用 |
| 形狀 | 角括號、十字刻度（缺口本身就是識別特徵） | 不用 |

**現制＝第二類的雙向暈**：主線帶當前墨色，內側暗暈、外側亮暈，各自漸淡。
四種情況全涵蓋——底亮 ⇒ 內暗暈拉開；底暗 ⇒ 外亮暈拉開；墨與底同暗 ⇒ 外亮暈仍在；
墨與底同亮 ⇒ 內暗暈仍在。最差是中灰底、兩側各約 0.5 的亮度差，**而那是不讀畫面
所能達到的下界**（黑與白之中必有一個與任何亮度相距 ≥0.5）。

因此第四版建的那整套底色亮度圖（64KB／人、每針記帳、洗墨重算、每幀 Jacobian）
**已全部拆除**——它是對的解法，但暈用更小的代價達到同樣的保證，留著就是死碼。

**畫法必須是實體環帶，不能用線段拼圓**（user：「為什麼會斷斷續續的」）：Canvas 的
線是平頭端點（轉角留楔形缺口），而不足一像素的線寬在無抗鋸齒的光柵化下整段被跳過。
環帶相鄰段共用頂點 ⇒ **接縫在數學上不存在**。

## 閘門（防這一頁自己過期）

- `Tools/UiCheck/hud_loc_lint.py`：`GUARDED` 名單（作畫相位 8 個函式）裡出現會上畫面的
  裸英文字面量就 exit 1。**它在第一次跑就抓到我漏的 5 條**——包括兩個我以為已經刪掉的
  `STENCIL` 針尖標籤（我只刪了 LINER/SHADER 那一份）。負向測試：把一條裸字串塞回
  `DrawInkChip` ⇒ 為正確的理由失敗。
- `NiceInkLocText.cpp` 的 `static_assert`：鍵數與 13 語表列數不一致＝**編譯失敗**。
  舊寫法 `GTable[COUNT]` 少一列照樣編得過（補 nullptr）＝執行期空字串的無聲失敗。
  負向測試：加一個沒有對應列的鍵 ⇒ 編譯以該訊息失敗。
- `Tools/UiCheck/tray_layout_check.py` / `tray_cursor_check.py`：版面與游標增益。
  **09-03 擴充**：三支筆各跑一輪版面（216 檢查），並新增 `c0a~c0j`＝**從 C++ 原始碼
  抽出真相來對賬**（`bColorAxis`／`bTierAxis`／`NumCols`／`NumRows` 的式子、
  `BeginStroke` 的分檔 alpha 條件、稿筆恆結晶紫、chip 的兩個條件、滾輪的作用域、
  數字鍵快捷確實消失）。**第一版的 `c0` 是空洞契約**——它拿閘門自己的 `NEEDLES`
  表跟自己比對（同義反覆），負向測試把 stencil 改回 10×3 照樣 ALL PASS。
  負向測試腳本逐條把 C++ 弄壞，確認**只有**對應那一條為正確的理由開火（7/7）。
