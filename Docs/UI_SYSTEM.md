# Nice Ink — UI 系統規範（UI System）

> **這份文件的唯一理由：畫面沒有人擁有。**
> 2026-09-02 的事故（`LINER` 同時出現在三個地方）已經由
> `Docs/DRAW_HUD_INVENTORY.md` 在**作畫相位**內部解決；但那份清單只管一個相位。
> 全遊戲有 **9 個相位 ＋ 7 個選單頁 ＋ 3 種特殊視野**（沉睡／裝睡／開場動畫），
> 而其中只有一個相位有人在管。這份文件管的是**跨相位的那一層**。
>
> 分工：
> - **SPEC.md** ＝設計的唯一權威（玩法、機制、承重不變量）。本文件不做設計決定。
> - **本文件** ＝畫面的憲法：分區職責、載體選擇、操作語言的形式、每個相位要說哪一句話。
> - **DRAW_HUD_INVENTORY.md** ＝作畫相位的逐元素清單（本文件的第一個實例）。
> - **NiceInkUiTokens.h** ＝數值正本（字級／間距／顏色）。**本文件不寫數值，只寫規則。**
>   註解裡的常數會過期而沒有東西看著它（專案鐵律）。

### 1.1 他們的「操作提示」不是鍵帽＋動詞，是一套**輸入片語文法**

一修我寫成「鍵帽＋2~5 字動詞」。**實物有三個成分，而且可以組合**：

    [動作圖示]  [輸入 glyph 序列]  動詞
                 ↑ 可以用 + 串接、可以上下堆疊成替代綁定

實例（paint mode 左緣圖例，預告片第 6 格）：

| 圖示 | 輸入 | 動詞 |
|---|---|---|
| 滴管 | `[SPACE]` | `3Dスポイト(長押し)` ← **長按這件事寫在動詞裡** |
| 左右箭頭＋筆 | `[滾輪 glyph] ＋ [CTRL]` | `ブラシサイズ` |
| 光芒 | `[V]` | `影` |
| — | `[右鍵 glyph]＋[移動 glyph]` **／** `[ALT]＋[左鍵]＋[移動]` | `カメラ回転` ← **兩組替代綁定上下堆疊，共用一個動詞** |
| — | `[滾輪 glyph]` **／** `[ALT]＋[右鍵]＋[移動]` | `ズーム` |

**滑鼠不寫 `RMB`——畫一隻滑鼠，把那顆按鈕點紅。** 這是「鍵位要畫成鍵盤上的樣子」
這條規則的完整版：**滑鼠沒有刻字，所以它的「字形」就是那隻滑鼠的圖**。

**鍵帽底色帶狀態**：截圖 1 底部 `[CTRL 青] しゃがむ`／`[CTRL][SPACE] 綠 立ち上がる`
——組合鍵**包在同一個深色圓角容器裡**＝一個動作。截圖 1 右緣 `[2 綠][3 綠]` 是切換開關，
截圖 2 的 `[1 黃] 挑発` 是一次性動作 ⇒ **顏色在區分「切換／動作／當前狀態」，不是重要性**。

### 1.2 他們**有**一套教規則的東西，而且是常駐的

右下角永遠掛著：**綠色模式名 ＋ 兩行規則**。英文版實物：

    If you get caught, you become a hunter.
    Hide until the end to win

日文版是 `増え鬼` ＋兩行。**這是「怎麼玩」的答案，不是「按哪顆鍵」的答案**——
兩者是不同的東西，他們用不同的區塊、不同的顏色、不同的字級各講一次。

## 二、兩個載體，一套語言

| 載體 | 用在哪 | 為什麼是它 |
|---|---|---|
| **Slate C++**（`SNiMenu`） | 主選單七頁（Root/Host/Join/Settings/Credits/Language/Profile） | 需要毛玻璃半透明白卡、文字輸入、清單捲動——canvas 做不到（08-06 user 裁決） |
| **Canvas**（`ANiceInkHUD`） | 局內全部（含大廳、ESC 選單、沉睡黑屏） | 每幀跟著世界走、零資產、與 3D 同一條繪製時序 |

**兩者共用**：`NiHudColor`（顏色）／`NiType`（字級角色表）／`BuildCompositeUiFont`
（六文字系統矩陣）／FlowDirection 鏡像規則。**樣式只有一套，載體有兩個。**

**選哪個的判準**：需要**打字或捲動** ⇒ Slate；其餘一律 canvas。
（新增第三個載體＝新增第三套樣式，永遠不要。）

## 四、操作語言（唯一形式）

### 4.1 形式＝輸入片語（**09-03 二修：從「鍵帽＋動詞」升級**）

    [動作圖示?]  [glyph 序列]  動詞
                  ↑ `A ＋ B` 串接；替代綁定上下堆疊共用一個動詞

- **glyph**：鍵盤鍵＝淺底圓角鍵帽＋深色鍵名（`DrawKeycap`，已有）；
  **滑鼠＝畫一隻滑鼠、把那顆按鈕點紅**（待做）；滾輪＝滑鼠＋上下箭頭；
  移動＝滑鼠＋四向箭頭。**鍵盤有刻字所以寫字，滑鼠沒有刻字所以畫圖。**
- **長按／點按的差別寫進動詞**（`3Dスポイト(長押し)` 的作法），不要另造一個視覺通道。
- 動詞＝**動作**不是名詞（`沾墨` 不是 `墨杯`；`指認` 不是 `嫌疑人`）。
- 鍵名**不翻譯**（鍵盤刻字）；動詞**必須進字串表**。
  **動詞長度隨語言變（英文 2~4 字、日文 2~7 字）⇒ 版面一律量測寬度驅動，禁止寫死欄寬。**
- **動作圖示是選配**：只在「動詞說不清楚這個動作長什麼樣」時加（筆寬、相機旋轉）。
  我們的三支筆在針尖的視覺本來就不同，不需要圖示（見 `DRAW_HUD_INVENTORY` 已刪清單）。

### 4.2 何時列、何時不列（鐵則）
- **軸不存在的時候，它的輸入、它的格子、它的操作表那一行都不該存在。**
  留著一顆按了不會有事的鍵，玩家會以為是自己弄錯了。
  （實例：`SCROLL 灰洗` 只在打霧筆列出，因為濃度只有打霧吃得到。）
- **一件事只講一次**，講在會被讀到的地方。
- **要背 vs 不用背**才是砍通道的判準：任意映射（數字↔顏色）砍掉，
  自然映射（滾輪↔濃度：有序手勢配有序軸）留著。

### 4.3 資料驅動（**待做，本文件的第一號工程**）
現況：每個呼叫點手寫 `Rows.Add({ TEXT("Q"), ENiLocKey::ActNeedle, false })`。
目標：一張 `FNiControlHint { EKey, ENiLocKey, EAvail }` 表，由相位／狀態查詢，
鍵形由**輸入裝置**決定（Meccha 的 `T_InputDeviceDatas` 對應物）。
**沒有這一層，手把支援或改鍵功能一到就要全站重寫。**

### 4.4 鍵帽底色的語義（**收斂**）
現況 `bAccent` 語義是「這條最重要」。**改成「現在可按 / 現在不可按」**
（Meccha 的作法），重要性交給排序（第一列＝這個狀態下唯一要學的動作）。
一個視覺通道只能有一個語義。

## 六、本地化（畫面上每一個字）

- **正本＝`NiceInkLocText`（13 語）。畫面上任何會被讀的字都必須是一個鍵。**
- 例外只有兩類，各自要有理由：①鍵名字形（鍵盤刻字）②純版型格式（`%d / %d`）。
- **閘門＝`Tools/UiCheck/hud_loc_lint.py`**。現況 `GUARDED` 只含作畫相位九個函式
  ——**這是誠實的邊界標記，不是完成度**。
  目標：`GUARDED` 擴到 `NiceInkHUD.cpp` 全檔（＝這份規範的完成定義之一）。
- 血價：「我以為我刪掉了」要用工具查不要用記憶查——lint 第一次跑就抓到我漏的 5 條。

5. **同一語義同一顏色**——兩隻滑鼠的高亮鍵用兩種紅＝在說兩件事。
6. **一個視覺通道只承載一個語義**（§4.4 的 `bAccent` 收斂同理）。

## 九、法務邊界（**抄之前先分清楚在抄什麼**）

> 我不是律師，這一節是工程上的操作邊界，不是法律意見。真要保險，上架前把最終截圖
> 給 IP 律師看一次是便宜的保險。

**著作權保護的是「表達」，不保護「想法／功能／慣例」。** 所以同一句「照抄」要拆成兩件事：

| 抄的東西 | 類別 | 判斷 |
|---|---|---|
| 右緣縱列、常駐、隨情境增減 | 版面**慣例** | 安全。這是整個品類的通用作法，不是誰的財產 |
| `[圖示][glyph 序列] 動詞` 的**文法** | **系統／方法** | 安全。著作權明文不及於 method of operation |
| 鍵帽＝圓角方塊＋鍵名 | 慣例 | 安全（Blender／Unity／大量遊戲都是這樣畫鍵） |
| 「滑鼠畫成滑鼠、按鈕點紅」的**概念** | 慣例 | 安全 |
| 右下角「模式名＋兩行怎麼贏」的**結構** | 慣例 | 安全（派對遊戲通用） |
| **他們的圖示檔案／滑鼠圖／沙漏圖** | **表達** | **不可用。自己畫。** |
| **他們的字串**（`Toggle X-Ray Rendering`／`隠れつづけよう`） | **表達** | **不可用**——而且我們的規則不同，抄了也是錯的 |
| 從 `.pak`／`.ucas` **抽出任何資產** | **表達＋契約** | **絕對不做。** 研究期讀過資產索引（檔名）＝調查手段；**任何抽出物都不得進 repo、不得進包** |
| 他們用的字型 | 授權 | `MPLUSRounded1c`／`ZenKakuGothicNew` 是 OFL，**要用就從 Google Fonts 合法取得**，不從他們的包裡拿。（但我們 08-06 已定案自己的字體矩陣，沒有理由換） |

**trade dress（商業外觀）**要成立，需要「有識別性」＋「會造成混淆」。近白鍵帽＋深字是
業界標準、不具識別性；而我們的畫面是紙／墨／相撲道場，與他們的螢光綠躲貓貓不會混淆。
**真正會踩到的是「整體抄成一個 clone」**——那不在我們的路徑上（不同品類、不同玩法）。

**可攜結論：抄文法，不抄字形。** 圖示一律用我們自己的美術語言重畫（墨線／筆觸），
這同時是法務要求與美術要求——**照搬他們的白色扁平圖示到紙墨介面上本來就會很怪。**

### 10.2 抄的是**規則**不是**值**（本輪的總方法）

§9 的「抄文法，不抄字形」原本只用在法務上。它其實是整件事的總方法，而且更嚴格一層：

### 10.3 唯一一條**不能照抄**的：他們的世界是暗的

「常駐 chrome 無面板」成立的前提是背景亮度有上限。實測：

    Meccha 的 chrome 背景亮度：27 / 80 / 84 / 155（最亮是打光的綠地板）
    我們的道場障子牆：        208  ⇒ 上緣祈使句對比 **1.27**（近乎隱形）

我原本假設「他們白字的描邊比較強、照抄就好」——**實測推翻**：他們字邊比背景暗
1.7~27 階，我們 7.7~10，同一個量級。**差的不是手法，是前提。**

⇒ 自己發明但守住規則的意思：**上緣一道沒有邊界的漸層壓暗**（`DrawTopScrim`）。
面板有邊界所以它是一個東西，漸層沒有邊界所以它是光線。

**兩次自己抓到的錯**（都寫進程式碼註解，不要再犯）：
1. 一版讓 alpha 從頂端 smoothstep 收到底 ⇒ **最暗的地方在沒有字的最上緣**，字所在處
   只剩 0.06；對比 1.27 只修到 1.89（仍不及格）。**地是給字用的，不是給邊緣用的**
   ⇒ 內容區維持峰值、只有內容下方才淡出。
   *教訓：閘門量到「有改善」不等於「修好了」——要對著門檻看，不是對著改善量看。*
2. 二版用 48 個 `DrawRect` 疊漸層 ⇒ robo 抓到 `cruise tipSpd` **2.05**（上限 2.00、
   基線 1.97）。改成 **1×64 貼圖一次 `DrawTile`**：視覺更平滑、成本回到常數。
   *這是同一個坑的第三次（09-03 兩次）：每幀成本會沿針的離散步進洩漏進手感。*

### 10.7 這一輪的方法論血價（**四條都是閘門自己在說謊**）

1. **`ui_token_audit` 的 ③④⑤ 是寫死的 `print`，不是量測**。⑤ 引用的

   ④ 寫死一句「局內沒有 serif 旗標」，於是明朝體接進局內之後它照樣報 FAIL。
   **閘門抄一份結論在自己身上，那份一定會過期**——這是本專案第四次踩。
2. **`/**墨**` 被當成塊註解開頭**：`ui_coverage`／`ui_token_audit` 的 `strip_comments`
   先剝 `/* */` 再剝 `//`，而 HUD 裡有一行行註解寫著 `/**墨**＝地對比…`
   ⇒ naive 正則一路吃到下一個 `*/`，**實測吞掉 10,918 個字元**，剛好蓋住
   `BuildControlHints` ⇒ 操作列整欄報 0/14。**既有的潛伏 bug，只是這次被吞的範圍
   剛好蓋到要讀的函式。** 修＝先剝行註解再剝塊註解。
3. **`phase_consistency` 找的是舊的綠色**：規則塊標題改酒金之後它報「規則塊 0/10」
   而畫面上明明有。同型第二次。
4. **負向測試選錯受測物**：我拿「修改前」的設定頁去測「內容壓到力士」，量到 1px
   ——因為修改前**有白卡，而白卡正是用來擋住力士的**。真正的失效模式是
   **拆掉卡片之後內容還留在中央**。改成拿現在的截圖、把取樣窗移回舊的置中位置，
   量到 123,726 px（門檻 8,000）＝閘門真的有解析度。
   *可攜：負向測試要打中「你這次修的那個失效模式」，不是「修之前的那張圖」。*

### 10.10 二修（2026-09-05，user viewport 打回：「這是什麼排版？」）

一修我把 `HAlign` 從置中改成靠左，**卻沒有改那個為置中而設計的構圖**。實測後果：

    左緣三種：75（標題）／106（主按鈕）／80（底列）＝極差 31px
    垂直空洞：310px ＋ 322px ＝ 螢幕高度的 58% 是島與島之間的空白

**三個病因，全部是「舊制度的殘骸留在新制度裡」**：

1. **106 = 72 + `NiSpace::CardPadH`(32)** ——那是**白卡的內距**。內距是給「卡的邊」
   用的，沒有卡就沒有邊要閃，它變成一個沒有理由的縮排。（已歸零＝`NiMenuGroundPad`）
2. **三帶構圖**（標題頂／卡置中／底列貼底）是為了「中間那張卡」而生的。卡不見了，
   中間那一帶就只剩兩個 `FillHeight` 撐出來的空洞。**已改成一疊**：主按鈕、狀態行、
   次要動作列收在左下同一條軸上（Meccha 的首頁就是這樣）。
3. **`SwayCm = 180` 的理由寫在它自己的舊註解裡——「每趟穿過毛玻璃卡後面」**。
   卡拆了，那個理由不存在，而值留著 ⇒ 力士走到畫面左半，設定頁的數值疊在他皮膚上。
   **新制＝內容靠左、場景佔右，由舞台自己遵守**：從幾何反推（內容欄右緣 x=632 →
   world Y +79.3cm、體半寬 ~84.6cm）得 `StageBiasCm = -76`、`SwayCm = 71`。

連帶修掉：底帶未替左下 `[ESC] Back` 讓位 ⇒ 設定頁的 Licenses 與它疊在一起
（`NiMenuBottomReserve = 56`）。

**可攜鐵則：拆掉一個東西的時候，要一起拆掉「為了它而存在」的所有常數。**
白卡拆了，它的內距、它撐出來的構圖、為了繞過它而設的舞台幅度——三個都還在，
而它們各自都曾經是對的。

### 10.11 我的閘門為什麼沒擋住（**這一節比修法值錢**）

一修的 `menu_measure` 報「單一左緣軸 PASS」，而 user 的 viewport 上一眼就看得到三條
左緣。原因：**它只比了「六頁之間的**標題**左緣」，對「同一頁之內」完全沒有解析度。**
這正是本文件 §7 那條鐵則要問的：**什麼樣的壞會讓它照樣亮綠燈？**

補的過程本身又踩了三次同型的坑，值得記：

- **顏色啟發式三版都不穩**：`lit`（不是黑）⇒ 力士被算成版面；`lit & ~skin` ⇒ 他身上
  **過曝的高光**逃出膚色述詞；改用調色盤 ⇒ 深底按鈕只被看見**裡面的字**（按鈕框太暗）。
  三個症狀互斥 ⇒ **我在錯的層**。對齊軸是**版面事實**不是影像事實：
  **判準搬去讀原始碼**（頂層 slot 的左內距只能有一個值、`CardPadH` 不得殘留），
  像素那一版降級為佐證。負向測試：同一組判準套在 HEAD 上 ⇒ 開火（29 處置中殘留＋CardPadH）。
- **膚色述詞把反鋸齒後的 Paper 文字算成皮膚**（Paper 邊緣 (206,197,182) 剛好落進述詞）
  ⇒ 量到「力士最左 x=72」，結論整個反過來。改成**要求一欄有 150 列以上連續膚色**
  （力士是實心大塊，文字最高 40px 又是鏤空的）。
  **述詞要能分開你要分開的那兩類東西，否則它只是在回答別的問題。**

## 十一、2026-09-05：中性制（user 作廢 08-06 白卡明朝制；本節取代 §二～§三的載體與顏色描述）

**user 定案（原話）**：「我其實只是想要一個成熟、適合的 UIUX 系統、設計，要讓這個遊戲看起來
像是大廠的設計，而不是像現在一樣的半成品樣……中性、簡約、通用的設計就足夠了，不需要太多
花裡胡哨的設計，讓遊戲內容站出來」→「我打算作廢，改成簡約中性的設計」→「可以的話就開始」。

### 11.1 診斷：半成品感的四個來源（不是設計語言）

1. **留白是用「什麼都沒有」做的**：選單＝黑虛空加一隻力士。簡約與未完成的差別在於留白是
   用什麼做的；大廠的簡約選單後面永遠有一個被構圖過的世界。
2. **系統只蓋到六成**：祈使句 12/14、操作列 7/14、規則塊 6/14。做好的畫面各自都好，
   整個產品仍讀成半成品——大廠的樣子九成是「沒有例外」。
3. **零動態**：選單與 HUD 的轉場、淡入、hover 動畫**一行都沒有**（實測 grep）。靜態截圖
   再好，動起來的第一秒就被讀成 mockup；而驗收一直只看靜態截圖，所以看不見。
4. **口吻不一致**：Title Case 與全小寫並存、大廳浮著一塊 debug 表、「文A」孤立圖形鈕、
   上緣壓暗讀成灰霧。

**08-06 那套（紙／墨／酒金／明朝）不是中性**：暖 UI 疊暖世界（皮膚、木頭、榻榻米）分離度
天生不夠（酒金動詞對皮膚 1.41、紙色對障子牆 1.27），而且它在說「日本、紙、墨」——世界
已經用相撲、和彫、障子說過一次，UI 再說是重複不是襯托。大廠讓內容站出來的手法幾乎都是
反過來的：**世界有色、UI 無色**。

### 11.2 系統（正本＝`NiceInkUiTokens.h`）

### 12.1 診斷（一句）
