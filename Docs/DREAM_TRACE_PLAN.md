## 實作總圖（2026-08-02 BUILT，robo 全綠）

- **生成器**＝`DreamTrace.h/.cpp`（`FDreamTraceGen`，純函式決定性）：割糖餅輪廓
  ＝諧波徑向閉圓 r(θ)=R0(1+Σ a_k cos(kθ+φ_k))（k=2~6、振幅預算 Σ|a_k|=Wobble）
  →縮放到目標周長→均勻弧長重採樣（0.25cm 步）。**自交避讓鐵律**：弧距 >3cm
  的點對歐氏距離 ≥2.6×帶半寬（投影窗唯一性的構造保證）；違反＝決定性衍生種子
  重試、諧波振幅 0.9^n 逐次收斂（必然收斂到近圓）。難度檔（DefaultParamsForCup）：
  周長 45/65/90cm×帶半寬 0.60/0.50/0.42cm（純描時間 ≈25/36/50s@v_max 1.8cm/s
  ＝回合時長主旋鈕）。統計儀器＝`DebugTraceStats`（三檔×200 種子：重試 0、
  minSelfDist 2.8~2.9 遠高於需求 1.1~1.6）。
- **元件**＝`DreamTraceComponent`（受害者 client 本地、不複製——作畫者看不到夢
  的進度）：**割線機制 2D 移植**——滑鼠=意圖點（純積分）、針以 `TattooMaxSpeed-
  CmPerSec()`（=1.8cm/s）恆速追趕、皮繩鉗（`TattooChaseLeashCm` 同值）、LMB
  按住=下針、下針瞬間游標收回針上（起點重合語義的持針版）、抬針=針凍在原地。
  **兩座標系**：盤面（針/游標＝你的手，搖晃時螢幕上不動）vs 圖形（=盤面−搖晃
  偏移；路線帶/已描墨/投影判定都在這）——圖被搖走、手沒跟上＝針在圖上滑出帶。
- **越線=重來**：下針中針心離中線 >帶半寬＝失敗——墨全洗、針回起點、進度歸零、
  **同一張圖**重描（路線記憶=玩家資產、可歸咎於手）；紅閃＋「SLIPPED」＋UiClick。
  進度＝投影窗（CurIdx±3cm）帶號弧長累積，|ProgressS|≥周長−0.35cm＝描完→
  `ServerTraceComplete`（驗證同 ServerMazeExited：ValidateMazeSender）→bEyesOpen。
- **搖晃攻擊**（`HandleShakeAttack`）：G 鍵（作畫階段非受害者）→server 驗相位/
  身分/現金/冷卻→扣 500→受害者 `ClientApplyShake`（顯名）＋攻擊者 `ClientShakeAck`
  ＋`PersistCharacter` 立即入檔。搖晃＝非諧和頻率連續偏移（振幅 1.2cm、2s、
  0.15s 進場/0.35s 收斂）。**無聲甦醒零洩漏鐵則**：受害者已睜眼**照收照扣**
  （拒收＝有錢過冷卻卻被拒＝唯一解釋「他醒了」）——夢端靜默失效（連音效都
  不給）、砸空=攻擊者自擔的賭。旋鈕：ShakeAttackCost/Seconds/AmpCm/CooldownSec。
- **噴射拳腳封存**（#51）：`GNiceInkSprayEnabled=false`（NiceInkTypes.h，與既有
  kick 閘同構）——Q 輸入／ServerSpray 伺服器拒收／HUD 技能列三閘；程式保留
  非刪除。robo 契約=零投射物+charges 恆 0。
- **迷宮退役接線**：EnterSeating 改發 `ClientStartTrace(Seed, Params)`（ArtistIds
  洗牌隨陷阱制一起退役）；DreamMaze 元件/RPC/robo 鉤子全保留但永不啟動；
  HUD 沉睡面板 trace 分支優先、maze 分支封存在後。
- **HUD**：受害者＝描圖盤（帶+羽化裙/墨/起點金圈/針/游標✕/進度%/搖晃顯名
  /失敗紅閃）；作畫者＝G 提示（idle 與 lean 兩條 hint 都有）＋購買回執閃示
  （「DREAM SHAKEN -$500」/「SHAKE REFUSED」——不透漏夢內結果）。

## 實作補位設計（SPEC #50 已標注、待 user 追認）

- 攻擊者對受害者顯名（怒氣要有地址——沿迷宮兇手公開原則）；其餘玩家不通知。
- 冷卻 4s（金錢是主限流、冷卻是節拍保底）。
- **搖晃期間抬針＝安全**：攻擊買到的是「強迫暫停」，硬描過去才會翻車。
- 費用佔位 500（連動 SPEC 待定 #6/#18 金額錨定）。
- 失敗重描＝同一張圖不換（dalgona 語義：學到的路線是你的）。
- 描圖方向自由（順逆時針都行；帶號弧長累積、繞完一圈即完成）。

  複雜度）；深杯變長=失誤率=可歸咎。
- **手感同源→整圖入鏡勘誤（同日 user 兩問打回）**：首版做了「px/cm 對齊割線

- **可描性雙鐵律＋離線鐵閘**：自交避讓（2.6×帶）＋**曲率半徑 ≥2cm**——首版

## 08-11 分杯重校＝D_shape 量化難度＋帶寬統一 2.2（user 定案）

### 問題

原分杯依據＝`feats`（曲率特徵數量），只數轉彎個數不量銳度。user 質問「複雜度
怎麼量化量測出來的？」→檢查後發現 feats 漏掉兩個維度：轉彎的**銳度**和**密度**。
結果：蛇（feats=11, 杯1）實際比鳥居（feats=24, 杯2）難描——feats 把鳥居的大量
緩彎當成「複雜」，漏看蛇的 31 次銳轉和 40.2° 最銳角。

### 難度公式推導（從玩家操作原理正推，非從結果反推）

**失敗只發生在轉彎**（直線段針穩定追蹤、偏差趨近零）。轉彎時路線突然轉向，
玩家需要反應時間 τ 調整滑鼠方向。在 τ 內游標繼續往舊方向跑，橫向偏移
δ ≈ v × τ × sin(θ)。人的反應時間有分布，轉角越大「來不及」的概率越高——
單次轉彎失敗概率隨 θ **超線性增長**。整條路線描完不失敗＝每個轉彎都沒出事，
任何一個失敗＝重來，所以總風險是所有轉彎風險的**累加**。

**D_shape = Σᵢ max(0, θᵢ − 3°)²**

- θᵢ = 每個取樣點（0.25cm 間距、432 點）的轉向角
- 3° = 噪聲底線（低於此的微彎零威脅，濾掉）
- 平方 = 銳轉權重遠大於緩彎（40° 轉 ≈ 28× 一個 10° 緩彎）
- 不含帶寬（帶寬是外部旋鈕，圖案本身的難度獨立於帶寬）
